🦟 Rift Valley Fever Transmission Model

A hybrid individual-based / ODE coupled model for simulating RVF dynamics between rainfall, mosquito vectors, livestock hosts, and human spillover — with a Streamlit web interface for parameter exploration, ensemble uncertainty quantification, and intervention planning.

Washington State University · Graduate Research Project · Last updated May 2026

1 · What Is This Model?

Rift Valley Fever (RVF) is a rainfall-driven zoonotic disease caused by a phlebovirus transmitted primarily by Aedes and Culex mosquitoes to livestock (cattle, sheep, goats) and secondarily to humans through contact with infected animals or mosquito bites. Outbreaks follow heavy rainfall events that trigger mass mosquito emergence.

🎯
Core goal: Simulate how RVF spreads through a livestock population under varying rainfall conditions, so researchers can predict outbreak timing, estimate the effect of interventions (vaccination, vector control), and understand which parameters drive risk most.

2 · Model Equations

🦟 Vector ODE

dSv/dt = β(t)·D(t) − λv·Sv − μ·Sv dEv/dt = λv·Sv − (σ+μ)·Ev dIv/dt = σ·Ev − μ·Iv
  • β(t) = α·rlag/(1+rlag) — rainfall-forced emergence
  • D(t) = max(0, 1−Nv/K(t)) — density factor
  • λv = b·phv·Ih/Nh
  • Stepped daily via Euler integration

🐄 Host IBM (Daily Step)

λh = (b/Nh) · pvh · Iv P(S→E) = 1 − exp(−λh) [each animal] E→I after latent_days I→R after infectious_days
  • Each of Nh animals tracked individually
  • Infection sampled stochastically per animal per day
  • Disease progression deterministic (fixed durations)
  • Stochasticity produces run-to-run variability

👥 Human ODE (Spillover)

dSh/dt = −λhuman·Sh dEh/dt = λhuman·Sh − Eh/Lh dIh/dt = Eh/Lh − Ih/Dh dRh/dt = Ih/Dh λhuman = (b/Nhum) · pvh,hum · Iv
  • Continuous ODE (humans too numerous for IBM)
  • Receives infection from vectors only (dead-end host)
  • Separate reporting fraction ρhuman

Observation Model

obs_cases(t) ~ NegativeBinomial( mean = ρ · new_inf(t), overdispersion = k )

The negative binomial captures both under-reporting (ρ < 1) and extra variance (k controls overdispersion; larger k → closer to Poisson).

R₀ Formula (Next-Generation Matrix)

R₀ = b · √[ pvh · phv · m · σ / ((σ+μ) · μ · γh) ] where m = Sv0/Nh (vector-to-host ratio at DFE) γh = 1/infectious_days R₀_hv = b·phv·m·σ / (γh·(σ+μ)) [host→vector contribution] R₀_vh = b·pvh / μ [vector→host contribution] R₀ = √(R₀_hv · R₀_vh)

4 · What Is Built So Far

Feature Status Where Description
Livestock IBM ✔ Done model/rvf_hybrid.py Each animal tracked individually through S→E→I→R. Stochastic infection sampling each day.
Rainfall-forced vector ODE ✔ Done model/rvf_hybrid.py Daily Euler integration of Sv/Ev/Iv with lagged, smoothed rainfall driving mosquito emergence. Density-dependent carrying capacity.
Host–vector coupling ✔ Done model/rvf_hybrid.py Daily bidirectional force of infection: infectious vectors → livestock and infectious livestock → vectors.
Syndromic observation model ✔ Done model/rvf_hybrid.py Negative-binomial sampling of reported cases with configurable reporting fraction ρ and overdispersion k.
Human spillover compartment ✔ Done model/rvf_hybrid.py ODE-based SEIR for humans. Infected by vectors only (dead-end host). Separate reporting fraction.
Ensemble / multi-run ✔ Done run_ensemble() Runs the stochastic model N times with sequential seeds. Returns 2-D arrays (runs × time). App shows median ± 90% CI bands.
Interventions ✔ Done InterventionParams Vaccination (mass campaign, configurable day/coverage/efficacy), vector control (increases mosquito mortality μ), movement restriction (reduces biting rate b). Comparison tab overlays baseline vs intervention.
R₀ calculator ✔ Done compute_r0() Next-Generation Matrix formula. Returns R₀, R₀_hv, R₀_vh. App displays gauge dial + component bar.
Sensitivity analysis (PRCC) ✔ Done run_sensitivity() Latin Hypercube Sampling across 8 parameters + Partial Rank Correlation Coefficients. Tornado chart shows which parameters drive total infections most.
Observed data overlay ✔ Done App Tab 9 Upload a day/cases CSV to compare against model-predicted reported cases. Supports ensemble bands.
CSV rainfall input ✔ Done App sidebar Upload any day,rainfall_mm CSV. Sample 365-day synthetic rainfall included. Two-column or single-column accepted.
Results export ✔ Done App Tab 9 Download full results as CSV (all compartments, ensemble percentiles, human data if enabled).

5 · App Structure & Output Tabs

📊 Tab 1 — Overview

  • 3-panel time-aligned chart: rainfall / SEIR / vectors
  • Switches to ensemble median + 90% CI when n_runs > 1
  • Shared x-axis for direct temporal comparison

🐄 Tab 2 — Host Dynamics

  • SEIR stacked-area chart
  • Daily new infections bar chart
  • Cumulative infections + running attack rate
  • Ensemble incidence fan when available

🦟 Tab 3 — Vector Dynamics

  • Sv / Ev / Iv compartment curves
  • Total mosquito population over time
  • Infectious fraction (%) time series

🔗 Tab 4 — Transmission

  • True infections vs reported cases (bar + line)
  • Force of infection proxy over time
  • Phase portrait: Ih vs Sh (time-coloured trajectory)

👥 Tab 5 — Human Spillover

  • Human SEIR stacked area
  • Daily human infections + reported cases
  • Cumulative human infections + attack rate
  • Shown only when human spillover enabled

💉 Tab 6 — Interventions

  • Auto-runs no-intervention baseline
  • Overlay: new inf., Ih, Iv, cumulative
  • Reduction % annotation on cumulative panel

🎯 Tab 7 — R₀ & Sensitivity

  • R₀ gauge dial (green/amber/red zones)
  • Component breakdown: R₀_hv and R₀_vh
  • PRCC tornado chart (on demand)
  • Significance table with p-values

🌧️ Tab 8 — Rainfall Analysis

  • Raw vs smoothed rainfall comparison
  • Lagged rainfall series used for emergence
  • Scatter: rainfall vs daily vector emergence

📥 Tab 9 — Data & Export

  • Upload observed case data for overlay
  • Full results table (all compartments)
  • Download CSV (includes ensemble percentiles)
  • Parameter summary table

6 · What Comes Next

⚡
Items are ordered by research impact. The first three transform the tool from a demonstration into something publishable. The remainder add polish and advanced capability.
1 · Scenario Comparison (Save & Compare Runs) High impact
Currently each click of Run replaces the previous result. Adding named scenario slots lets you save "Baseline", "High rainfall", "Vaccine at day 30" as separate runs and overlay them on the same chart.
  • Add a "Save this run as…" button with a text label input
  • Store up to 4 saved runs in st.session_state.saved_scenarios
  • New "Compare Scenarios" tab overlays all saved runs on incidence, vectors, and cumulative panels
  • Useful for: comparing interventions, comparing rainy seasons, parameter sweeps
2 · Real Rainfall Data Pull (CHIRPS / NASA POWER API) High impact
Instead of uploading a CSV, enter a GPS bounding box and date range and automatically pull real historical daily rainfall from a remote-sensing product.
  • Integrate CHIRPS (Climate Hazards Group InfraRed Precipitation) API — 0.05° resolution, daily, 1981–present
  • Or NASA POWER (free REST API, no key required) for point-location data
  • Add a "Fetch rainfall" form: latitude, longitude, start date, end date
  • Immediately enables running the model against real RVF outbreak years (2006–07 East Africa, 2010 South Africa, etc.)
3 · Parameter Calibration (Fitting to Observed Data) High impact
Right now all parameters are set by hand. For the model to be scientifically credible it needs to be fitted to at least one real outbreak dataset.
  • Use scipy.optimize.minimize (SLSQP / Nelder-Mead) to minimise negative log-likelihood between obs_cases and uploaded observed data
  • Or implement a basic ABC (Approximate Bayesian Computation) rejection sampler for posterior distributions over key parameters
  • Output: best-fit parameter values, confidence intervals, goodness-of-fit metrics (AIC, correlation, RMSE)
  • New "Calibration" tab in the app
4 · PDF / HTML Report Export Medium
Generate a self-contained report after each run that includes all charts, the parameter table, KPI summary, and R₀ value — suitable for sharing with collaborators or supervisors.
  • Use Plotly's .to_html(full_html=False, include_plotlyjs="cdn") to embed interactive charts
  • Assemble a single HTML file with the report (no PDF library needed — browsers can print-to-PDF)
  • Add "⬇ Download Report" button in Tab 9
5 · Multi-Species Livestock Medium
RVF affects cattle, sheep, and goats differently — sheep have much higher case fatality rates. The current model treats all hosts as identical.
  • Add a species field to the Host dataclass
  • Add a SpeciesParams config with per-species latent days, infectious days, p_vh, and mortality rate
  • Sidebar: sliders for fraction of cattle / sheep / goats in the herd
  • New output: species-disaggregated incidence curves
6 · Early Warning Score Medium
Automatically flag days when conditions are favourable for outbreak initiation — useful for alerting systems and operational decision-making.
  • Compute a daily "risk score" = weighted combination of lagged rainfall, vector population, and R₀ estimate
  • Add threshold lines + colour-coded risk zones (green / amber / red) to the Overview chart
  • Optional SMS/email alert stub for deployment scenarios
7 · Spatial Extension (Multi-Patch) Advanced
Add a spatial layer of connected patches (farms, districts) with livestock movement between them — RVF can spread along livestock trade routes.
  • Each patch has its own SEIR-IBM + vector ODE + rainfall time series
  • Movement matrix (n_patches × n_patches) controls daily animal movement rates
  • Output: animated maps of infection spread
  • Requires significant refactoring of the simulation loop
8 · Age & Pregnancy Structure Advanced
Pregnant animals have much higher mortality and abortion rates from RVF. The current model ignores age and reproductive state.
  • Add age and pregnant fields to the Host dataclass
  • Modify infection outcomes: pregnant animals have higher p(death) and p(abortion)
  • Track abortion events as an additional output (key surveillance signal)
9 · Online Deployment (Streamlit Cloud) Ready now
The app is already structured for deployment. Only a GitHub push + Streamlit Cloud connection is needed.
  • Push repo to GitHub (public or private)
  • Connect at share.streamlit.io — free tier, permanent URL
  • Add .streamlit/config.toml for custom theme if desired
  • Share URL with collaborators, supervisors, and funders
